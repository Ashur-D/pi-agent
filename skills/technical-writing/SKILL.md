# Technical Writing

Write clear, unambiguous technical documentation that a reader understands on the first pass.

## Core Rules

1. **Cut every word that does no work:** If a sentence survives without a word, drop it ("In order to" becomes "To").
2. **Use short, everyday words:** "Use" over "utilize", "help" over "facilitate", "show" over "demonstrate".
3. **Write exact names:** Code identifiers, protocols, tool commands, file names, and error strings should be written verbatim.

## The Diátaxis Structure (Select the matching document type)

- **Tutorials (Learning-oriented):** Walk through an exercise step-by-step from zero to a working result. Show expected outputs at each milestone.
- **How-To Guides (Problem-oriented):** Solve a specific task or troubleshooting problem. Assume basic familiarity. Focus on actions and results.
- **Reference (Information-oriented):** Technical specifications, parameter tables, command syntax, and configuration keys. Structured for quick lookup.
- **Explanation (Understanding-oriented):** Dissect background, architectural decisions, protocol interactions, and trade-offs.

## Rhythm and Formatting

- Vary sentence length: Mix concise, punchy statements with descriptive sentences.
- Use numbered lists for sequential steps and bullet points for unordered items.
- Always provide reproducible code snippets with terminal commands clearly delineated.
- Avoid abstract jargon; state what actually happens at the system or network level.
